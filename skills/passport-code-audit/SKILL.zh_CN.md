# 固件完成后的严格审计

**固件实现完成后**、agent 宣布完成、交给真机测试或发布之前，必须执行本审计。
构建通过不构成跳过理由。本审计不替代构建门禁或真机验收，而是补充它们没有
覆盖的代码证据审查。

先阅读项目 `AGENTS.md`、`PROJECT.md`、AI 开发指南、贡献与安全规则及相关
构建／测试指南。用 `git rev-parse --show-toplevel` 确定项目根目录，不要审计
安装后的技能目录。

## 1. 固定候选版本

1. 记录 `git rev-parse HEAD`、`git status --short --branch`、任务范围和准确
   构建命令。审计过程中不提交、不推送、不烧录。
2. 找出改动文件及其调用方。审计改动行为及受其影响的共享代码；不要把无关
   失败扩大进当前任务。
3. 记录固件身份及可用的设备／串口产物。过期或无法识别的二进制不能当作
   本次候选审计。

## 2. 运行仓库门禁并收集信号

至少运行项目文档规定的门禁：

```bash
./tools/validate.sh --static
# 先激活所需 ESP-IDF 环境：
./tools/validate.sh
```

Windows 上 PowerShell 无法执行 `./tools/validate.sh`：优先用项目自带的
`tools\validate.ps1` / `tools\validate.cmd`，只有 `.sh` 时通过 Git Bash 运行。
在报告里写明实际运行的是哪一个门禁。

运行本次改动所需的宿主测试，并在审计技能 base 目录执行：

```bash
python3 <base>/scripts/scan_code.py --root <项目根目录> --json
# Windows：py -3 <base>\scripts\scan_code.py --root <项目根目录> --json
```

扫描器只是**辅助信号**，会报告不安全调用、堆调用、阻塞延时、整屏重绘、
疑似密钥字面量和待办标记；它不能证明内存安全或流畅性。每条命中都必须结合
上下文人工复核，不能把“扫描无输出”当作审计通过。

## 3. 合规审查

按 [`references/checklist.zh_CN.md`](references/checklist.zh_CN.md) 审查所有
改动代码及集成点：

- **内存与边界：** 所有权、生命周期、边界、整数溢出、空值与错误路径、
  栈／堆上限，无释放后使用或无界增长。
- **并发与界面：** LVGL 锁的持有范围正确且短；渲染／输入回调内不得执行
  阻塞的 Flash、网络、文件或串口操作；任务栈和优先级合理；循环可被看门狗
  接受；退出清理完整。
- **安全与密钥：** 源码、日志、截图或提交的捕获中不得含凭据、token、设备
  密钥；不得执行不安全的命令；网络／TLS 与输入校验符合功能需要。
- **项目与法律合规：** 仓库规则、许可证与第三方声明、生成产物；不得禁用
  检查或压制警告，不得遗留调试代码，不得擅自改依赖或分区。
- **恢复路径：** 失败状态可见且有界；不得无限重试、静默降级或执行破坏性
  修复。

## 4. 流畅性与运行时审查

静态审查不能证明流畅。沿用 Gate 0 的预算，或先记录明确预算，然后在真机上
对代表性场景预热并按约定时长采样：

| 测量项 | 需要的证据 |
| --- | --- |
| 帧节奏 | 渲染／显示耗时或面板完成节奏；丢帧 |
| 输入响应 | UP/DOWN/OK 短按／长按／双击延迟，漏触或重复触发 |
| 内存 | 空闲／最小堆、最大连续块、有 PSRAM 时的占用 |
| 稳定性 | 看门狗复位、分配失败、崩溃、黑屏、撕裂 |
| 热路径 | 无忙等、逐帧分配、长延时、整屏重绘或阻塞日志 |

使用项目阈值；没有阈值时先记录明确预算，不得把未测量的结果说成“流畅”。
串口截图只能证明像素，不能证明动画；应与测量数据一起作为视觉证据。无法
访问设备时报告 `NOT RUN`，不是 PASS。

## 5. 严重度与阻塞规则

- **P0：** 崩溃、数据损坏、密钥泄露、安全或许可证违规、无界内存、关闭安全
  门禁。阻塞完成与发布。
- **P1：** 可复现卡顿／冻结、输入丢失、界面阻塞、泄漏、看门狗风险、误导性
  失败处理。阻塞完成与发布。
- **P2：** 可维护性或非阻塞文档问题。记录；经用户决定可延后。

修复 P0/P1，重跑受影响的测试、构建、截图和测量，再重复审计。不得为了过门禁
降级发现，也不得在必需门禁为 `FAIL` 或 `NOT RUN` 时宣称审计通过。

## 6. 写审计记录

创建简明记录（例如 `docs/audits/<候选版本>-code-audit.md`），包含候选身份、
命令与结果、发现表、测量数据，以及 Build、Host tests、Compliance、
Smoothness、Device 分项结论。只对实际观察的检查写 `PASS`；列出 `Unverified`。
本审计不隐含提交、推送、烧录或发布。
